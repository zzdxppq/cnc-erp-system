## Epic Context
**Epic**: 1 - Foundation & Core Infrastructure
建立项目基础架构。系统服务提供用户管理、权限控制、工作流引擎、数据字典等基础能力。
API网关统一处理路由、认证鉴权、日志记录。数据库设计遵循模块化原则，为后续业务扩展预留空间。

## Acceptance Criteria

### AC1: User registration and JWT authentication

**Scenario**
```gherkin
GIVEN User is not registered in the system
WHEN User submits valid registration data via POST /api/auth/register
THEN
  - New user record is created in database
  - Password is hashed using bcrypt with cost factor 12
  - Response returns 201 with user object (excluding password)
  - JWT access token is generated (15 min expiry)
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-1.1 | Email must be unique across all users |
| BR-1.2 | Password must be 8-32 characters with at least one uppercase, one lowercase, and one digit |
| BR-1.3 | New accounts are created with status 'active' |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| email | email | true | RFC 5322 compliant, max 255 characters | 请输入有效的邮箱地址 |
| password | string | true | 8-32 chars, must contain [A-Z], [a-z], [0-9] | 密码必须8-32位，包含大小写字母和数字 |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| Email already registered | 409 | 该邮箱已被注册 | 返回错误，建议登录或找回密码 |
| Password does not meet requirements | 400 | 密码不满足安全要求 | 返回具体的不满足项 |

---

### AC2: User login with credentials

**Scenario**
```gherkin
GIVEN User has an active account
WHEN User submits valid credentials via POST /api/auth/login
THEN
  - JWT access token is generated (15 min expiry)
  - JWT refresh token is generated (7 day expiry)
  - Tokens are returned in response body
  - Last login timestamp is updated
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-2.1 | Failed login attempts are tracked; lock account after 5 consecutive failures |
| BR-2.2 | Account lockout duration is 15 minutes |
| BR-2.3 | JWT access token contains: user_id, username, roles |

**Data Validation**
| Field | Type | Required | Rules | Error Message |
|-------|------|----------|-------|---------------|
| email | email | true | Valid email format | 请输入邮箱地址 |
| password | string | true | Non-empty string | 请输入密码 |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| Invalid credentials | 401 | 邮箱或密码错误 | 不提示具体哪个字段错误，累计失败次数 |
| Account locked | 423 | 账户已锁定，请15分钟后再试 | 返回剩余锁定时间 |

---

### AC3: Role-based access control (RBAC)

**Scenario**
```gherkin
GIVEN User is authenticated with JWT token
WHEN User attempts to access a resource without required role
THEN
  - Response returns 403 Forbidden
  - Response includes error message '权限不足'
```

**Business Rules**
| ID | Rule |
|----|------|
| BR-3.1 | System defines roles: admin, salesman, engineer, planner, buyer, warehouse_staff, qa, operator, finance, hr |
| BR-3.2 | Each role has specific permissions (create/read/update/delete on specific modules) |
| BR-3.3 | Admin has all permissions by default |

**Error Handling**
| Scenario | Code | Message | Action |
|----------|------|---------|--------|
| Token expired | 401 | 登录已过期，请重新登录 | 返回401，前端跳转登录页 |
| Insufficient permissions | 403 | 权限不足 | 返回403，提示需要何种权限 |

## Dev Notes

### Technical Constraints
- JWT tokens: HS256 signed, contain user_id/username/roles claims
- Password hashing: bcrypt cost factor 12
- Account lockout: 5 consecutive failures triggers 15-minute lockout
- Database: MySQL 8.0, snake_case naming

### Accumulated Context (From Previous Stories)
> First story - no accumulated context yet

### Database Design
- **users** table: id (UUID PK), email (unique), password_hash, status, failed_login_attempts, locked_until, last_login_at, created_at, updated_at, created_by, updated_by, deleted_at (soft delete)
- **roles** table: id, name (unique), description, created_at, updated_at
- **user_roles** junction: user_id (FK), role_id (FK)
- **permissions** table: id, role_id (FK), module, action (enum: create/read/update/delete)
